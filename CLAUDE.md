# Furniture CAD (furniture_v9)

Browser CAD for cabinet furniture: build cabinets from panels, auto-generate joinery drilling (confirmat / minifix / rafix / dowels / shelf pins / hinges), export cutting lists and NC drilling programs. User speaks Russian — reply in Russian.

Stack: React 18 + TypeScript (strict) + Vite 5, three.js via @react-three/fiber + drei, zustand, vitest. No git. Deployed as static site on Render (`render.yaml`).

## Commands
- Typecheck (use to verify changes, ~12s): `npx tsc --noEmit -p .`
- Tests (domain invariants, ~1s): `npm test` — `src/domain/__tests__/`. Add a case when fixing layout/joinery bugs.
- Build: `npm run build` · Dev: `npm run dev`

## Token rules
- Big files — never Read whole; Grep for the symbol, then Read with offset/limit:
  `app/store.ts` (~1600 lines), `ui/inspector.tsx` (~1800), `domain/cabinet-layout.ts` (~1000), `editor/scene-root.tsx` (~1000). Domain modules under `domain/cabinet/` and `domain/auto-joinery/` are ≤ ~580 lines — keep them that way: a new rule goes into its own file, not into an existing big one.
- Ignore: `node_modules/`, `dist/`, `package-lock.json`.
- Files are UTF-8 with Cyrillic. In PowerShell never write files via `Set-Content`/`>` without `-Encoding utf8` — use Edit/Write tools.

## Architecture (all paths under `src/`)
- `domain/` — pure logic, no React.
  - `part.ts` — `Part` (panel: width/height/thickness mm, position/rotation, `operations`, `meta`: groupId, role `PartRole`, cabinetLayout, cabinetOptions, joinery, parentSectionId…). Max size 2800.
  - `drill.ts` — `MachiningOperation = DrillOperation | GrooveOperation`. `DrillOperation` (face, x/y on face, diameter, depth, through, `feature`, `autoGenerated` meta, `source`); `GrooveOperation` (face, x/y → x2/y2 centre line, width, depth). Code that means holes filters with `isDrillOperation`. `getFaceAxis`.
  - `project.ts` — `Project` + immutable ops (add/update/remove parts, drill groups by `getDrillGroupToken`).
  - `cabinet-layout.ts` — `CabinetLayout` tree: tiers → sections → partitions/shelves/drawer stacks/tier dividers; `resolveCabinetLayout`, `resolveCabinetTierLayouts`, mutators (`splitSection`, `addShelfToSection`, …).
  - `cabinet-builder.ts` — barrel (public API only); code in `domain/cabinet/`: `types`, `constants`, `common` (dimensions, back inset, options), `frames` (tiers/zones), `back-panel`, `drawers`, `plinth-crown`, `fronts` (openings/fronts), `build` (`buildSimpleCabinet` = `createCabinetBuildContext` + steps `build-interior`/`build-back-panels`/`build-plinth-rails`/`build-fronts`), `module-state` (state, `rebuildCabinetGroup`, layout edits). — `buildSimpleCabinet(input)` → parts for a cabinet group (sides, top/bottom, back panel/aprons, fronts, drawers, plinth, top rails) + builder-owned drilling (drawers, plinth, crown). `rebuildCabinetGroup`, `getCabinetModuleState`, layout-section edit wrappers. Calls `applyGeneratedJoinery`.
  - `auto-drilling.ts` — barrel; code in `domain/auto-joinery/`: op creators by place (`core` helpers/source tags, `top`, `back-panel`, `horizontal`, `aprons`, `hinges`) and the pass `apply` (`applyGeneratedJoinery` = per cabinet `createGroupJoineryContext` + steps `apply-carcass`/`apply-fronts`/`apply-back-panels`/`apply-shelves`/`apply-aprons`/`apply-dividers`). — `applyGeneratedJoinery(parts, rules)`: regenerates auto ops (tagged via `source`) per joint type: `create<Where><Type>Ops` (Top/OverlayTop/BackPanel*/Partition*/Horizontal/BottomPartition/Apron*/ShelfPin/FrontHinge). `getDefaultAutoJointRules`.
  - `module-split.ts` — `planModuleSplit`: how a cabinet over the 2800 mm sheet limit is built from several modules (UI hint `ui/sheet-limit-hint.tsx`, action `splitCabinetIntoModules`).
  - Confirmat + dowel (`confirmat-dowel`, 26163 carcass joint): `auto-joinery/confirmat-dowel.ts`, world-geometry based (`createConfirmatDowelJointOps`: edge part → host face; host through Ø7 / edge 34, dowel 11 / 22; grid 32 from 69, last hole ≥ 53 from the back, +32 with an overlay HDF — `jointBackReserve`; partition joints only front+back pairs). Wired for top/bottom/partitions/dividers only (not back panels, aprons, shelves).
  - `joinery.ts` (`JoineryType`, `SideJoinery`), `drill-spacing.ts` (conflicts, normalize), `geometry.ts` (bounds, snap, relative placement), `templates.ts` (hole templates), `validation.ts`.
  - `face-coords.ts` — the only face-local ↔ world conversion (`getFacePointWorld`, `projectWorldPointToFace`); don't re-implement it.
  - Drawer block (`CabinetDrawerStackSpec.block` in `cabinet-layout.ts`): owns its local dividers (inner + optional base for a niche), placed in mm by the builder; zones are named after the divider below (`zone-base`, `zone-above-<dividerId>`).
  - Auto joinery runs once: `buildSimpleCabinet` returns raw parts, `rebuildCabinetGroup(parts, groupId, draft, rules)` applies it.
  - Back panel kind (`backPanelKind`, cabinet option): `panel` (board of carcass thickness, fastened), `hdf-overlay` (3 mm sheet nailed on the back edges, 2 smaller than the carcass on every side — `HDF_OVERLAY_EDGE_INSET`, inner parts full depth, no joinery) or `hdf` — one 3 mm sheet 6 mm larger than the opening in grooves (`HDF_GROOVE_*`: 14 from the back edge, 5 deep, through) on sides/top/bottom, joinery none; inner parts stop at the groove (`getBackInset`). Cabinet option `withHangers` (adjustable wall hangers) cuts 20x30 notches in both top HDF corners: `Part.cornerNotches` (XY-plane plates only), outline `getPartOutlineXY`, drawn by `NotchedPanelGeometry`, cut as the contour in «переделка». Grooves are builder-owned (`generated-groove:`), rendered by `GrooveMarkers`, exported as T1 in «переделка».
  - Aprons: top/bottom by the cabinet option `withAprons`, shelves by `CabinetShelfSpec.withApron`; built after back panels and skipped where a back panel covers the spot. New back panels get confirmat on all edges in `meta.joinery` (explicit `none` = no joint).
  - Fronts: `CabinetFrontSpec` in each tier layout (`fronts`) — section + bottom/top boundary ids (shelf / local divider / `OPENING_EDGE_*`), kind door/double/flap, hinge. Openings (`getCabinetOpenings`, cells between boundaries, read from built parts) are picked in 3D with the toolbar front tool `activeTool: 'place-front'` (`SectionOverlay` shows every cabinet's cells; Shift+click extends; `selectOpening` also selects the cabinet and section in one update). `selectionMode` has no UI toggle and stays 'part', so nothing may rely on 'group' mode to be reachable; `setFrontOnOpening` replaces overlapping fronts (in any tier); a tall front spans tiers along a column of lined-up cells (`getOpeningRange`, `extendOpeningRef`; spec keeps `topTierId`/`topSectionId`, stored in the bottom cell's tier), and the overlay merges the cells under a front into one; an inset front over a tier/local divider sets that divider back by `INSET_FRONT_INTERNAL_RECESS` (like shelves in inset mode); a front with a vanished boundary or over drawers is not built. Front parts: `sourceId` `front:<specId>[:left|right]`, hinge side lives in the spec; `meta.hingeType` (overlay at an outer panel / half-overlay at a shared one / inset) is set by `getHingeType` and named in the hinge cup template. Hinge plates are marked, not drilled: `createHingePlateMarkOps` puts a pair of 2 mm marks (37 from the carcass front, 32 apart around the cup) on the panel found at the hinge edge. Front placement rules are in `getFrontRect`, also used for overlay drawer fronts (cabinet `frontMode`; the box then comes up to the carcass front). Overlay gaps (`OVERLAY_FRONT_*`, from 26163 labels): 2 at a carcass side and top, 0 at the bottom, 4 between fronts (doors and stacked drawer fronts). Hinges sit 82 (122 for 3+) from the line the gap is measured from, i.e. 80 from a front's end, 82 at a bottom-flush end (`getHingeEndGaps`).
  - Top over the fronts (`topOverFronts`, cabinet option; overlay fronts + overlay top only, excludes top rails): the top reaches forward by a front's thickness (`meta.frontOverhang`), fronts stop under it; top joinery is laid out on `withoutFrontOverhang(top)` and shifted back (`shiftOpsForFrontOverhang`). Module depth comes from the sides.
  - Drawer block `fill`: drawers take the whole section beyond the niche; the inner divider spec stays in the layout but is not built (`applyDrawerBlockDividers`, `getDrawerBlockZones`). Drawer boxes follow their front (an overlay front may reach over the bottom panel). Overlay fronts never cover a frame plinth: at the cabinet bottom they stop at the bottom panel, so the lowest drawer box keeps its height.
  - Kitchen plinth on legs (`plinthKind: 'kitchen'`, `cabinet/kitchen-plinth.ts`, 26163 pencil 2_02): one plinth set back 8 (confirmat to sides at 50 from floor, confirmat+dowel to the bottom), leg holes in the bottom and leg marks on the sides, fronts go down to 30 from the floor (`floorClearance` in `getFrontRect`), the bottom's front side pair becomes one confirmat at 37. Back rails (`backRailElevations`, role `back-rail`, 250 high, flush with the back, confirmat+dowel to the sides) are builder-owned (`generated-back-rail:`).
  - Presets: `domain/cabinet-presets.ts` (`CABINET_PRESETS`, `buildCabinetPreset`: body → drawer blocks → doors via `setFrontsOnAllOpenings`), store `addCabinetPreset`, buttons in the quick-cabinet panel. A preset may set its own fastening (`backPanelJoinery`, minifix for dresser/nightstand/TV stand) via `applyPresetJoinery`, applied after the quick-cabinet fastener choice. Back panel bottom fasteners step off holes already in the host's under face (plinth rail dowels) — `getBackPanelBottomOffsets`.
  - Kitchen mode (`kitchenMode` in the store, localStorage, checkbox in the «Экспериментальное» block of the shortcuts dialog): the kitchen plinth kind and back rails fields show only in it (or when a module already uses them).
  - Drawer block false panel (`CabinetDrawerBlockSpec.falsePanel`: side + gap from the section wall): role `drawer-false-panel`, full height/depth of the block zone, joined top/bottom like `drawer-column` (confirmat by default, rafix picked on the part); drawer boxes run beside it, fronts still cover the whole section.
  - Shelf drag: Shift+drag a shelf in 3D (`editor/shelf-drag.tsx`, logic `domain/shelf-drag.ts`: range between neighbours, 25 mm magnet to shelves/dividers of other sections), committed as the shelf `elevation` via `moveShelfToHeight`.
  - Default active section (nothing picked): `getDefaultTierSection` — the tallest tier. Hole tool (Ø/depth/through) lives in the toolbar; the click on a face places it.
  - Output: `cutting-list.ts` (list, sheet plan, CSV), `nc-export.ts` (`buildNcProgram`, `buildPresadkaFiles` — «присадка» drilling files; edge M-codes and X come from the part frame `getPresadkaFrame`: u along the label's first size — height for standing parts, width for lying ones; M601/M603 run along u, M604/M602 along v, M603/M602 counted from the far end), `peredelka-nc.ts` (`buildPeredelkaFiles` — «переделка» face machining + contour, «обратная сторона»; the contour is the Ø6 cutter centre path, 3 mm outside the part, so front-side holes/grooves are shifted by `CONTOUR_CUTTER_RADIUS` — Part sizes are real (cut) sizes, reference contours are 6 larger; both byte-checked against Basis fixtures in `__tests__/fixtures/`), `part-label.ts` (localized part names).
- `app/store.ts` — single zustand store `useAppStore`: project in undo history (`editor/commands.ts`, last 100 steps), selection (part/face/group/section/drill), drafts (cabinet/hole/move/jointRules), view flags, all user actions. Helpers `useProject`, `useSelectedPart`. Autosave (`startAutosave`, ~1.2 s debounce) is started by `main.tsx` after restoring the saved project.
- `editor/scene-root.tsx` — 3D scene (R3F): parts (`PartMesh` memoized, boolean selectors), all hole markers in one InstancedMesh (`DrillMarkerInstances`), picking, measurement, snapping, zone overlays.
- `ui/error-boundary.tsx` — wraps scene and inspector; offers undo instead of saving a possibly broken state.
- `ui/` — `toolbar.tsx`, `inspector.tsx` (right panel, cabinet/section/part editors), `project-tree.tsx`, `sketch-window.tsx` (floating reference-drawing window, mounted in `App.tsx` over the whole work area so it can overlap the left panel; frame shows only on hover; pan/zoom/rotate/opacity; image data in `project.sketches` — `domain/sketch.ts`, `infra/sketch-image.ts`; window geometry in localStorage). `App.tsx` — layout, cutting list / export dialogs.
- `infra/` — `save-load.ts` (async, IndexedDB via `idb.ts`: key `furniture_v9:project-progress` + 5 slots; file open/save), `export-nc.ts`, `export-part-map.ts`.
- `i18n.ts` — `t(lang, key)`, dicts `en` + `ru`; add every new key to both.

Flow: UI → store action → domain function (pure) → new Project pushed to history → scene/inspector re-render. Cabinet edits rebuild the whole group via `rebuildCabinetGroup` (auto drilling regenerated, manual ops preserved).
